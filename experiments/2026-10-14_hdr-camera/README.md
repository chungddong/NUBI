# 2026-10-14 · 웹캠 노출 브라케팅으로 HDR 처럼 보기 (실시간)

> 상태: **동작 확인** — Jetson 에서 웹캠 하나로 짧게 · 중간 · 길게를 프레임마다 돌려 찍고 합쳐 웹 화면에 보인다.

## 1. 목적

복도 · 실습실처럼 창이 있는 곳에서 카메라 사진이 창은 하얗게 날아가고 그늘은 검게 묻힌다 (첫 주행 녹화). 노출을 여러 개
섞어 밝은 곳과 어두운 곳을 함께 살릴 수 있는지, Jetson 에서 실시간으로 되는지 본다. 위치 찾기 (SfM) · 모델 운전에 쓸
사진의 질을 올리는 후보.

## 2. 구성

- Jetson "mokpo", 웹캠 `WebCamera` (USB `32e6:9221`, UVC, MJPG 1280×720 30 fps)
- 웹캠 V4L2 컨트롤 (2026-10-14 읽음): 자동 노출 메뉴 (1 = 손으로, 3 = 자동), 노출 시간 1 ~ 5000 (0.1 ms 단위), 게인 0 ~ 63,
  밝기 · 대비 · 감마 · 화이트밸런스. `v4l2-ctl` 이 없어 ioctl 로 직접 읽고 쓴다.
- `hdr_view.py` — 웹 화면 `http://192.168.127.2:8094` (유선 직결 주소에만). `bash hdr_ctl.sh start | stop | status`.
  녹화기 (`../2026-10-13_vlm-drive/record.py`) 와 같은 웹캠을 쓰므로 둘 중 하나만 띄운다.

방법:
1. 자동 노출을 끄고 프레임마다 노출을 짧게 → 중간 → 길게 차례로 넣는다. 노출을 바꾸면 다음 프레임부터 반영된다 (아래).
2. 가장 최근 세 프레임을 밝기 순으로 정렬해 (어두운 것 = 짧은 노출) 640 px 로 줄이고 `cv2.createMergeMertens` 로 합친다
   (노출 시간 · 카메라 응답 곡선이 필요 없는 노출 합성).
3. '자동' 이면 1 초마다 중간 프레임 밝기를 목표 (기본 110 / 255) 에 맞추고, 짧게 = 중간 ÷ 2^EV, 길게 = 중간 × 2^EV
   (EV 기본 2). 중간은 33 ms 까지, 길게는 '긴 노출 최대' (기본 66 ms) 까지.

## 3. 결과

| 확인 | 값 |
| --- | --- |
| 노출을 바꾼 뒤 반영 | 다음 프레임부터 (버퍼 기본값으로 읽을 때 프레임마다 돌려도 짧게 37 · 중간 76 · 길게 141 이 정확히 반복) |
| 수동 노출 fps | 카메라 버퍼를 1 개로 줄이면 15 fps, 기본값이면 30 fps |
| 합성 시간 (Jetson CPU, Mertens) | 640×360 35 ~ 46 ms · 960×540 84 ms · 1280×720 166 ms |
| 실시간 (640 합성, 길게 66 ms 까지) | 카메라 21.9 fps · HDR 21.5 fps (노출 2.6 / 10.2 / 40.8 ms) |
| 눈으로 본 차이 | 중간 노출 한 장에서 하얗게 날아간 창 바깥 (창틀 · 걸린 옷 · 바깥) 이 HDR 에서 보이고, 그늘진 옷 · 의자도 더 밝다 |

한계: 세 장이 약 0.1 s 에 걸쳐 찍혀 빨리 움직이면 겹쳐 보인다 (정렬 안 함). 길게를 33 ms 넘게 주면 그 프레임만큼 fps 가
준다. 색 · 대비는 Mertens 특성상 약간 납작해진다.

## 4. 결론

실시간 HDR 은 Jetson CPU 로 된다 (640 px, 약 20 fps). 다음에 볼 것: 녹화기에 HDR 모드를 넣어 같은 복도를 다시 찍고, 위치
찾기 (SfM) 성공률이 늘어나는지 — 첫 녹화에서 웹캠은 관측 전부와 맞출 때 50 장 중 17 장만 찾았다. Xtion 컬러도 OpenNI 로 노출을
바꿀 수 있는지 확인.
