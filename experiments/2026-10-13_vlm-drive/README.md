# 2026-10-13 · GPT · Claude 실차 운전 (Jetson + ESP32 + Xtion)

시뮬레이터 ⑤ "GPT · Claude 운전" 과 같은 방식을 실차로 옮긴 것입니다. Xtion 사진에 깊이로 잰 갈 수 있는 방향을 번호
화살표로 그리고, 위에서 본 복도 지도와 오도메트리 추정 위치를 같이 모델에 보내 한 걸음씩 몹니다. 모델 호출 코드와
프롬프트는 시뮬레이터 것([agent.py](../../hardware/vehicle/models/vehicle/sim/agent.py) ·
[agent_claude.py](../../hardware/vehicle/models/vehicle/sim/agent_claude.py))을 그대로 부릅니다.

## 1. 목적

- 시뮬레이터에서 된 "사진 + 깊이 화살표 + 지도 + 추정 위치 → 모델이 한 걸음 결정 → 차가 닫힌 루프로 실행" 이 실차에서도
  되는지 확인한다.
- 그 전에 실차 쪽 기본기 — ESP32 링크 · 오도메트리 · 돌기 / 가기 · Xtion 깊이 · 사각 정지 — 를 하나씩 확인한다.

## 2. 구성

```
Xtion Pro Live ──USB 2.0 (OpenNI2)──►  Jetson Orin Nano "dongki"  ──USB 시리얼 115200 (CH340)──► LOLIN D32 (ESP32) ──UART──► 호버보드 보드 4장
                                       drive.py                                                    w 1 + h 하트비트, s · t · x
                                         └─ HTTPS ─► OpenAI / Anthropic API (agent.py · agent_claude.py)
```

### 시뮬레이터와 다른 점 (Xtion)

- 화각 약 58° × 45° (Gemini 336 은 90° × 65°) → 화살표는 ±24°, ±16°, ±8°, 0° 의 7 개.
- 약 0.5 m 안쪽은 깊이가 0 이다 (2026-09-17 RDK 가드에서 확인). 바닥이 0.65 ~ 2 m 에 보여야 할 줄이 비어 있으면
  그 방향을 '사각 → 막힘 0.3 m' 로 친다. 정면이 사각이면 가던 것도 선다.
- 카메라 장착 높이 · 숙임은 시작할 때 바닥면으로 잰다. 바닥이 안 보이면 `robot.json` 의 `camera_height_m` 를 쓴다.

### 바닥 보정 — 무엇을 어디서 재나

오도메트리는 **앞축 두 바퀴의 홀 스텝**만 센다. 그래서 거리는 앞바퀴에서, 방향은 한쪽 앞 · 뒤 바퀴 두 점으로 잰다.
차의 위치 (지도 위 점) 는 네 바퀴 접지점 한가운데 (REP-103 `base_link`, 바닥 z = 0) 로 본다.

| 치수 (차체 설계 v29) | 값 |
| --- | --- |
| 휠베이스 (앞뒤 축 사이) | 420 mm |
| 트레드 (좌우 바퀴 중심 사이) | 527.4 mm |
| 바퀴 바깥 지름 | 158.7 mm (실측) → 한 바퀴 498.6 mm. 허브 모터 한 바퀴 90 스텝이면 5.54 mm / 스텝 (지금 `robot.json` 5.76 은 [가정]) |

**표시 붙이는 법 (공통)** — 기준점은 바퀴 **축 중심 바로 아래 바닥**이다. 바퀴 바깥 면 (허브 덮개) 한가운데에 작은
십자를 붙이고, 직각자 (또는 수평계를 댄 자) 를 그 십자에 세워 바닥에 마스킹테이프 + 연필로 점을 찍는다. 바퀴가 굴러도
축 중심은 그대로이니 출발 전 · 멈춘 뒤 같은 방법으로 찍으면 된다. 바닥은 **실제로 다닐 복도 바닥**에서 잰다 (돌 때
미끄러지는 정도가 바닥마다 달라 `track_eff_m` 이 바뀐다). 배터리는 충분히 (40 V 근처).

**직진 → `m_per_step`** (`calibrate.py straight --runs 3 --write`)

1. 앞 2.5 m 를 비우고 바퀴를 똑바로 둔다. 앞 왼쪽 · 앞 오른쪽 바퀴 축 아래에 출발 점을 찍는다.
2. `y` → 2 s 동안 `fwd_cmd` (180) 로 간다 (약 0.6 ~ 1 m).
3. 멈춘 뒤 같은 두 바퀴 아래에 도착 점을 찍고, 바퀴마다 출발 점 → 도착 점 거리를 줄자로 잰다 (mm). 왼쪽 · 오른쪽을 따로 넣는다.
4. 세 번 하면 평균을 적는다. 두 값이 2 cm 넘게 다르면 가는 동안 틀어진 것 — 화면에 몇 도 틀어졌는지 나온다.

**한 바퀴 회전 → `track_eff_m`** (`calibrate.py spin --runs 2 --write` — 왼쪽 · 오른쪽 번갈아 돈다)

1. 둘레 1 m 를 비운다. 앞 왼쪽 · 뒤 왼쪽 바퀴 축 아래에 점을 찍고, 두 점을 지나는 **긴 직선** (마스킹테이프, 앞뒤로 50 cm
   씩 더 길게) 을 바닥에 붙인다.
2. `y` → 지금 `robot.json` 값으로 오도메트리가 한 바퀴 (360°) 가 될 때까지 돈다. 값이 틀린 만큼 실제로는 조금 더 / 덜 돈다.
3. 멈춘 뒤 같은 두 바퀴 축 아래에 점을 찍고, 각 점이 처음 직선에서 **수직으로** 떨어진 거리를 잰다 (mm, 직선 바깥 쪽 = +,
   차 밑 쪽 = −). 앞 · 뒤 두 값을 넣으면 실제 각도 = 360° ± asin((앞 − 뒤) / 420) 로 계산한다. 차가 옆으로 밀려나도
   두 점이 같이 밀리니 각도에는 영향이 없다.
4. 왼쪽 · 오른쪽 값이 따로도 나온다. 둘이 5 % 넘게 다르면 바퀴 공기압 · 무게 쏠림을 보고 `--runs 4` 로 다시 잰다.

### 안전

- 사람이 비상정지 버튼을 들고 따라간다. 처음에는 `robot.json` 의 `max_cmd` 300 · `fwd_cmd` 180 그대로 (느림).
- 모델은 장애물 정지에 끼지 않는다. 가는 중 깊이로 범퍼 앞 0.30 m (`stop_gap_m`) 안이 막히거나 정면이 사각이면 선다.
- 하트비트 임대: 모델 응답을 기다리는 동안 (수 초) 에는 하트비트를 보내지 않는다 → ESP32 가 "host watchdog" 으로 멈춘
  상태로 기다린다. 프로그램이 죽어도 1 s 안에 선다. 끝날 때 `w 0` 으로 워치독을 끄고 나간다 (ISSUES N2).
- 실물 사진에는 사람이 찍힌다. 기록 (`data/logs/vlm-drive/`) 은 git 에 올라가지 않고, 사진은 모델 회사로 간다 —
  학교 쪽 확인이 필요할 수 있다.

### 게임패드로 직접 몰기 (`pad.py`)

ESP32 핫스팟 웹 조종 (폰) 은 자주 끊기고 터치 버튼이라 조작이 거칠었다. 웹 경로에는 늦게 도착한 명령이 바퀴를 다시
돌리는 문제 등이 열려 있다 (펌웨어 ISSUES R1 · R2 · R4 · R5 · U3). 패드는 무선 구간이 패드 ↔ 전용 수신기뿐이고, 그 뒤는
Jetson → USB 시리얼 선 + 하트비트 워치독이다.

```
패드 ──2.4 GHz──► 수신기 (USB, Jetson) ──evdev──► pad.py ──USB 시리얼 (s · t · x · h)──► ESP32 ──► 보드 4 장
```

| 조작 | 하는 일 |
| --- | --- |
| START | 잡기 — `x` · `m 300` · `w 1`. 프로그램을 켜도 START 전에는 아무것도 보내지 않는다 |
| L1 누르는 동안 | 운전 허용 (데드맨). 떼면 바로 `x` (램프 없이) |
| 왼쪽 스틱 위아래 | 속도. 조금만 밀어도 움직이게 펌웨어가 0 으로 치는 50 부터 단계까지 |
| 오른쪽 스틱 좌우 | 조향 (+ = 오른쪽). 서 있으면 제자리 회전. 가면서는 바깥 바퀴를 왼쪽 스틱 세기 그대로 두고 안쪽 바퀴만 줄인다 — 반이면 안쪽 바퀴 0, 끝까지면 거꾸로 (제자리). 두 스틱을 다 놓으면 바로 `x` |
| 십자 위 / 아래 | 속도 단계 100 · 150 (처음) · 200 · 250 · 300 (`max_cmd` 가 상한) |
| R1 누르는 동안 | 한 단계 빠르게 |
| 십자 왼쪽 / 오른쪽 | L1 을 누른 채 (스틱은 놓고) 오도메트리로 제자리 90° 돌기 — `motion.turn_by` 와 같은 규칙 (`turn_cmd` · `turn_tol_deg` · `turn_min_dps`) 을 한 틱씩. L1 을 떼거나 스틱을 건드리면 멈춘다 |
| A | 주행 기록 시작 / 끝 — `record.py` 의 녹화기를 이 프로세스에서 같은 바퀴 링크로 (처음 누를 때 Xtion · 웹캠을 연다, 결과는 `data/logs/hallway-run/<시각>/`, 20 분 뒤 스스로 끝). 사진 5 Hz · 바퀴 보고 줄에 더해 웹캠 동영상 `webcam.mkv` (~30 fps) · 패드 입력 `commands.csv`, 끝나면 `preview.mp4` (세 카메라 나란히, 2 배속) 를 뒤에서 만든다 |
| B | 비상정지 — `x` 하고 놓는다 (잡지 않았어도 `x`). 다시 몰려면 START |
| SELECT | 놓기 — `x` · `w 0`. 폰 웹 조종으로 돌아갈 수 있다 (ISSUES N2) |

```bash
python3 pad.py show                 # 패드가 잡히나, 버튼 · 축 번호
python3 pad.py learn                # 안내대로 눌러 pad.json 저장 (패드를 바꾸면 다시)
python3 pad.py drive --fake         # 가짜 ESP32 로 패드만 시험 — s · t 값이 찍힌다
bash pad_ctl.sh start               # 실물, 뒤로. stop · status · log [줄 수]
bash pad_ctl.sh install             # 부팅하면 스스로 start (사용자 crontab @reboot, sudo 없이). uninstall 로 지움
```

- 안전: 잡은 동안 제어 루프가 돌 때만 하트비트 임대 → 프로그램이 멈추면 1 s 뒤 ESP32 가 선다. 수신기가 빠지면 세우고 놓는다.
  보고 줄이 0.6 s 끊기면 선다. 잡을 때 · 수신기가 다시 붙을 때 L1 이 이미 눌려 있으면 한 번 떼야 움직인다.
- 폰 웹 조종과 같이 쓰지 않는다 — 웹 버튼을 누르는 동안은 시리얼 `x` 가 덮인다 (ISSUES R7).
- 시리얼은 한 프로그램만 연다 (`open_serial` 이 리눅스에서 잠금). `bench.py` 가 돌고 있으면 먼저 끈다. 녹화도
  `record.py` 를 따로 띄우지 않고 A 버튼으로 한다 — 두 프로그램이 한 포트를 나눠 읽으면 보고 줄이 깨진다.
- 기록은 `data/logs/pad/pad.log` (재부팅해도 남는다 — `/tmp` 에 두었다가 재부팅 때 밖에서 몬 기록을 잃었다).
- Jetson 은 시계 배터리가 없다. 네트워크 없이 켜면 시각이 마지막 저장 시각부터 가므로 녹화 폴더 이름 · 로그 시각이 실제와
  다를 수 있다 — 녹화 `meta.json` 의 `clock_synced`, 로그의 '고리 시작' 줄에 동기화 여부를 남긴다.
- 수신기는 USB 3.0 포트 바로 옆 (2.4 GHz 잡음) 과 금속 차체 안쪽을 피한다. 거리가 모자라면 USB 연장선으로 위에 올린다.
- 권한: 바탕화면에 로그인한 사용자는 udev uaccess 로 `/dev/input/eventN` 을 읽는다. "mokpo" 는 gdm 자동 로그인 (`dongki`) 이라
  부팅 뒤 권한이 생기고, 그 전에는 `pad.py` 가 1 s 마다 다시 연다. 자동 로그인을 끄면 `sudo usermod -aG input dongki`.
- `start` 는 `pad.py` 가 끝나면 3 s 뒤 다시 띄우는 고리로 돈다 (부팅 직후 ESP32 가 늦게 잡혀도). 다시 떠도 놓은 상태라 바퀴는
  START 전까지 움직이지 않는다. 2026-10-14 부터 "mokpo" 에 `install` 해 두었다 — 이더넷 없이 전원만 켜면 패드 대기.

## 6. 결론

진행 중. 실차 1 ~ 5 단계를 해 본 뒤 적는다. 자리를 잡으면 ROS 2 패키지 (`software/ros2_ws/src/nubi_base` — cmd_vel ·
오도메트리, `nubi_perception` — 깊이) 로 옮긴다.

### 알려진 한계

- 위치는 오도메트리뿐이다 (스키드 스티어는 돌 때 미끄러져 방향 오차가 쌓인다). IMU (iAHRS) 와 SfM 시각 위치 인식은
  아직 붙이지 않았다 — 위치 인식 정확도는 [2026-10-13_sfm-relocalization](../2026-10-13_sfm-relocalization/) 에서 잰다.
- 지도에 가구 (회색) 가 없다. 지도는 벽 선과 문만.
- 반짝이는 검은 바닥 · 유리는 깊이가 비어 '사각' 으로 보일 수 있다 (보수적으로 선다).
