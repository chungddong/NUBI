# 차량 웹 시뮬레이터

버전 폴더의 메시 캐시 (`vNN_*/output/scene.npz`) 를 웹으로 옮겨 three.js 로 운전 · 센서 · 전원을 본다.
왜 만들었는지는 [`../DECISIONS.md`](../DECISIONS.md) D-18, 시뮬레이터로 본 결과는 D-19.

```bash
.venv/Scripts/python.exe models/vehicle/sim/web_export.py v27_sensor_module
```

```bash
.venv/Scripts/python.exe models/vehicle/sim/web/serve.py 8748
```

브라우저 → http://localhost:8748 (launch.json `vehicle-sim`). 버전을 바꾸면 web_export 를 다시 돌리고 새로고침.

### 환경 — 시험 코스 / 복도

패널 '환경 · 출발점' 에서 고른다 (`?env=hallway`). **복도**는 영상으로 복원한 실제 건물 3 층 복도 · 라운지
(`F:\Develop\hallway-3d`, scene.json 기준 벽 85 · 오브젝트 223, 문 23 개에 호수 이름). 2026-09 부터 원본은 사진 대신
텍스처를 코드로 그린다. 원본은 읽기만 하고 아래로 복사해 쓴다:

```bash
.venv/Scripts/python.exe models/vehicle/sim/import_hallway.py
```

→ `web/hallway/` (형상 코드 world/ · scene.json, 사진 텍스처는 원본에 있을 때만, gitignore). 원본 `buildArchitecture` · `buildObjects` 를 그대로 부르고
x 축 +90° 로 돌려 z 를 위로 (우리 (x, y, z) = 원본 (x, −z, y)). 충돌은 원본 충돌선 (벽 · 난간) + 고정 가구 상자 + 사람 2.
복도를 고치면 import_hallway 를 다시 돌린다.
천장 판과 천장에 단 것 (조명 · 감지기 · 비상구 표지) 은 three.js 레이어 1 에 둔다 — 내 화면에서는 숨기고 (패널 '천장 보기'),
앞 카메라 화면과 광선 투사 (깊이 · 라이다) 에는 들어간다. 깊이 점 중 차 높이 + 15 cm (0.68 m) 보다 높은 것은 밑으로
지나갈 수 있으므로 장애물도 바닥도 아니다 (점으로는 그린다).
버전 인자를 빼면 메시 캐시가 있는 마지막 버전.

## 조작

- `W` `S` 앞뒤 · `A` `D` 회전 (방향키도) · `Space` 비상정지 · `R` 처음 자리
- ③ 비상정지 방식 (A 즉시 차단 · B 정지 후 차단 · C 정지 유지 · D 차단 + 상선 단락) 을 고르고 '10° 경사에서 네 방식 비교'.
- ④ '목표 찍기' 후 바닥을 누르면 자율주행. 사람 2 명이 오간다 (막히면 1.2 s 뒤 돌아선다).
- ⑤ GPT · Claude 운전 (복도에서만): 목표 문 · 모델 · 생각 깊이를 고르고 '시작'. 아래 '⑤ GPT · Claude 운전' 참고.
- 검증용: 콘솔에서 `__sim.drive(v, w, 초)` · `__sim.run(초)` (자율주행 그대로) · `__sim.goal(x, y)` · `__sim.place('ramp15')` ·
  `__sim.estop(true)` · `__sim.estopTest()` · `__sim.cover.compute(0.3)` · `__sim.stab.set({m, h, x})` — 브라우저 패널이 숨어 화면 갱신이 멈춰도 돈다.
  **한 번에 10 s 안쪽으로** — 도구 시간 제한 (45 s) 에 걸린 스크립트는 페이지 안에서 계속 돌아 탭이 굳는다 (그때는 탭을 닫고 새로).
- 화면을 한 번도 안 그리면 matrixWorld 가 갱신되지 않아 광선 투사가 장애물을 원점에서 본다 → course.js 가 직접 갱신한다.
- 광선 투사는 **움직이지 않는 것을 월드 좌표로 한 메시에 합쳐 BVH (three-mesh-bvh 0.7.6) 하나**로 — 복도 (메시 443) 에서 한 번 재기 2.9 s → 21~35 ms.
- 점유 지도: 3 s 넘게 다시 안 보인 칸은 0.5 s 마다 줄인다 (지나간 사람 흔적), 깊이 점은 한 번 보이면 장애물.
  지금 길보다 1.5 배 (또는 4 m) 넘게 먼 길이 나오면 4 s 까지 기다린 뒤 돌아간다 (사람에 막혀 되돌아갔다 왔다 하지 않게).

## ⑤ GPT · Claude 운전 (카메라만)

VLMnav (Goetting 외, CoRL 2024) 방식. 매 걸음 앞 카메라 사진 한 장에 깊이 카메라로 잰 '갈 수 있는 방향' 7 개
(±40° · ±27° · ±13° · 0°) 를 번호 화살표로 그려 GPT 에 보낸다. 화살표 빈 거리는 앞 카메라 세로줄 44 개의 가장 가까운
장애물을 그 방향 띠 (차 반폭 + 여유 0.32 m) 에 비춰 잰다. GPT 는 `move` (화살표 · 거리) · `turn_left` / `turn_right`
(각도) · `stop` 중 하나와 '보이는 것 · 메모 · 까닭' 을 돌려준다 (Structured Outputs). 메모는 다음 걸음에 그대로 돌려준다.

- **주지 않는 것**: 진짜 위치 ('정답' 모드 빼고), 라이다. 진짜 위치는 행동 실행 (돌기 · 가기 — 실물에서는 바퀴
  오도메트리 · IMU 몫) 과 채점에만 쓴다. 가는 중에 깊이로 범퍼 앞 0.25 m 안이 막히면 선다.
- **지도 · 위치** (패널 선택, 기본 '지도 + 오도메트리 + 시각 위치 인식'): 위에서 본 지도 그림 (벽 · 고정 가구 · 문 호수 ·
  목표와 1 m 원 · 추정 위치 삼각형과 오차 원, 1280 × 472) 을 두 번째 사진으로, 지도 좌표 · 목표 문 앞 점 · 문 좌표 ·
  추정 위치를 글로, 화살표마다 지도 방향을 준다. 실물도 지도는 갖고 가지만 위치는 추정뿐이라 오차를 흉내 낸다 [가정]:
  - 오도메트리 — 출발점은 안다. 걸음마다 진짜 이동에 바퀴 축척 오차 (주행마다 ±3 %) · 걸음 잡음 2 % · IMU 방향 잡음
    0.5° 를 얹고 방향 오차만큼 돌려 쌓는다. 오차 원은 걸은 거리 × 4 %.
  - 시각 위치 인식 (SfM 흉내) — 걸음마다 80 % 확률로 진짜 위치 ± 0.15 m · ± 3° 로 바로잡는다.
  - '지도만' (위치 모름), '정답' (비교용 상한), '안 줌' (사진만 — 처음 방식) 도 고를 수 있다.
- **층 안내** (켜면): 복도 입구에서 들어가며 왼쪽 · 오른쪽 벽의 방 이름 순서 (`hallway_env.js` 의 doors). 좌표는 없다.
- **채점**: GPT 가 `stop` 하면 목표 문 앞 (문에서 0.8 m 안쪽 점) 까지 거리 ≤ 1.0 m 면 성공. 걸음 한계 40.
- **API 키**: 이 폴더에 `agent.local.json` 을 직접 만든다 — `{"openai_api_key": "sk-..."}` (저장소 공통 `*.local.*`
  로 git 제외, 서버가 걸음마다 읽으므로 다시 띄울 필요 없음). 또는 환경변수 `OPENAI_API_KEY` (서버를 다시 띄워야 함).
- **모델** (2026-10-13 가격, 100 만 토큰당 입력 / 출력): `gpt-6.1-sol` $2 / $10 · `gpt-6-astra` $10 / $50 ·
  `gpt-6-luna` $0.10 / $0.50. 사진 한 장은 detail high 로 약 1,250 토큰. `모의` 는 API 없이 연결만 시험한다.
- **Claude** (`agent_claude.py`, `pip install anthropic` — requirements.txt 에 있음): `claude-opus-5-5` $4 / $20 ·
  `claude-sonnet-5-5` $2 / $10 · `claude-haiku-5-5` $0.10 / $0.50. 프롬프트 · 출력 형식은 GPT 와 같다 (`agent.SYSTEM` ·
  `SCHEMA`), 생각은 adaptive, 깊이는 패널의 low / medium / high. 키는 `ANTHROPIC_API_KEY` · `ant auth login` 프로필 ·
  `agent.local.json` 의 `"anthropic_api_key"` 순.
- **서버 없이 몰기**: 콘솔에서 `__sim.agent.start({model: '이름'})` → `__sim.agent.observe()` (화살표 · 빈 거리만, 위치 없음,
  사진은 패널 `#agImg`) → `await __sim.agent.act({observation, memory, reason, action, arrow, distance_m, turn_deg})`.
  사람이나 다른 프로그램도 같은 사진 · 실행 · 채점으로 견줄 수 있다.
- **알려진 한계**: 렌즈가 17 cm 높이라 문 위 번호판 (1.8 m) 은 문 앞에서 시야 밖이고, 돌출 표지판 글자는 복도 입구에서
  1280 픽셀 사진으로도 읽히지 않는다. 그래서 멈출 곳은 지도와 추정 위치로 정하고, 사진은 장애물 · 문 모양 확인과 위치가
  맞는지 보는 데 쓰게 했다 (프롬프트). 복도 텍스처는 코드로 그린 것이라 실제 사진과 다르다 — 실물 화면 인식 정확도
  시험이 아니다.
- **움직이는 사람** (④ 칸 체크): 끄면 화면 · 광선 투사 (깊이 · 라이다) · 충돌에서 모두 빠진다 (2026-10-13 전에는 복도에서
  끄면 안 보이기만 하고 깊이 · 충돌에는 남았고, 시험 코스에서는 멈춰 선 채 남았다).
- **카메라** (패널 '환경 · 출발점' 의 카메라, `?cam=xtion`): 기본은 차체 설계의 Gemini 336 앞 · 뒤 (90° × 65°).
  'Xtion Pro Live 앞 하나' 는 지금 실차 카메라 — 화각 58° × 45°, 깊이 4 m 까지, **0.5 m 안쪽은 깊이 없음**. 바닥이
  0.65 ~ 2 m 에 보여야 할 광선이 0.5 m 안쪽에 막힌 비율이 60 % 넘는 세로줄은 '사각' 으로, 화살표에서 막힘 (0.3 m) ·
  정면이면 범퍼 앞 0 으로 친다. 화살표는 ± 24° · ± 16° · ± 8° · 0°, 보내는 사진 640 폭. 렌즈 자리는 설계의 앞 카메라
  자리 (높이 17.2 cm) 를 그대로 쓴다. 실차 쪽 같은 규칙은 [experiments/2026-10-13_vlm-drive](../../../../../experiments/2026-10-13_vlm-drive/README.md)
  `depth_view.py`. (2026-10-13 넣었고 브라우저 확인 전에 PC 가 멈춰 아직 화면으로는 확인하지 않았다.)
- 프롬프트의 카메라 사양은 요청의 `camera` 글로 넘긴다 (없으면 Gemini 336 사양). 화살표 줄에 '(사각)' 이 붙는다.

## 어림 · 가정

- 질량은 부품 부피 × 밀도 + 알려진 무게 (허브모터 3 kg 은 [가정]) — v27 에서 약 33.6 kg.
- 턱은 바퀴 반지름의 40 % (33 mm) 까지만 넘는다고 본다. 경사 · 턱 위 자세는 네 바퀴 닿는 높이로만 (서스펜션 없음).
- 전원: 상 저항 0.15 Ω · 효율 0.75 · 미끄럼 마찰 0.6 은 [가정]. 실측으로 고친다.
