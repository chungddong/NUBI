# 0001. 바퀴 보드 짝과 믹싱 — 축 단위 짝 유지, 믹싱은 ESP32로 (passthrough 마스터)

- 상태: 채택 (2026-10-13 바퀴 띄운 시험 통과, 바닥 주행 전)
- 날짜: 2026-10-13

## 배경

모터 보드 4장은 앞축과 뒤축에 마스터 + 슬레이브가 한 쌍씩 있습니다. 두 마스터는 오른쪽 바퀴에 붙어 있고(처음 이 결정을 쓸 때는 09-17 기록대로 "왼쪽"이라고 적었으나
같은 날 실측으로 바로잡음), ESP32가
마스터마다 UART로 (속도, 조향)을 보냈습니다(차체 설계 [D-03](../../hardware/vehicle/models/vehicle/DECISIONS.md),
바퀴 제어기의 보드 모드).

이 방식으로는 제자리 회전이 안 되고 회전도 약했습니다. 마스터 펌웨어(RoboDurden Gen2.x-GD32)의 믹싱이
곱셈식이기 때문입니다. 속도가 0이면 조향도 0이 되고, 풀 조향에서도 안쪽 바퀴는 역방향 듀티를 최대 약 12 %만
받습니다. 이 모터는 약 20 %는 있어야 움직입니다(2026-09-17 업스트림 분석, 09-18 Jetson 실측과 일치).

09-22에는 같은 쪽 앞 · 뒤를 한 짝으로 다시 묶고, 마스터가 슬레이브 부호를 뒤집지 않게 하는 패치
(`SLAVE_SAME_SIDE`)를 넣기로 했습니다. 그런데 그 빌드가 사라져서(ISSUES H1) 다시 만들어야 했고, 그 과정에서
더 간단한 방법을 찾았습니다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 보드 모드 유지 | 아무것도 안 바꿈 | 제자리 회전 불가, 회전 약함. 프레임으로 보내는 어떤 값으로도 못 고침 |
| B. 같은 쪽 앞뒤 짝 + `SLAVE_SAME_SIDE` (09-22 계획) | ESP32 탱크 모드를 그대로 씀 | 보드 3~4장 재플래시(역할 2장 맞바꿈), 4핀 케이블을 앞↔뒤로 다시 깔고 전원 버튼 이동, `main.c` 패치, 앞뒤 바퀴가 늘 같은 값 |
| C. 축 단위 짝 유지 + passthrough 마스터 | 배선 그대로, 마스터 2장만 재플래시, 업스트림 훅(`PILOT_USER`)만 써서 `main.c` 무수정, 바퀴 4개를 각각 제어 가능 | 프레임 `iSteer`의 의미가 바뀌어 ESP32와 마스터 버전을 맞춰야 함 |
| D. UARTBUS (보드 4장 독립 주소) | 완전 독립 제어 | 보드 4장 재플래시 + 새 프로토콜 + 보드 TX마다 쇼트키 다이오드 |

## 결정

**C**를 고릅니다. 마스터의 `Pilot()`에서 믹싱을 없애 프레임의 `iSpeed`는 마스터 바퀴, `iSteer`는 슬레이브 바퀴
듀티로 그대로 씁니다. ESP32가 `left = speed + turn`, `right = speed − turn`을 계산해 두 링크에 같은 (왼쪽, 오른쪽)을
보냅니다.

- 슬레이브 부호 반전은 그대로 둡니다. 축의 두 바퀴는 마주 보고 달려 있어서 같은 값이면 같은 방향으로 굴러갑니다.
  (x, x)는 예전 보드 모드의 "속도 x, 조향 0"과 같은 출력입니다.
- B보다 작업이 적고, D-03의 짝 구성과 맞습니다. 바뀌는 것은 믹싱 위치뿐입니다.
- B를 계획했던 이유는 09-17에 메인보드를 고칠 수 없는 조건에서 만든 탱크 모드를 4륜으로 늘리려던 것이었습니다.
  펌웨어를 고칠 수 있다면 믹싱 자체를 바꾸는 쪽이 작업이 적습니다.

확인한 것(2026-10-13):

- 마스터 빌드 17,884 B. 다시 빌드해도 SHA-256이 같았습니다.
- ESP32 빌드 Flash 61.5 %.
- 파이썬 모델(ESP32 믹싱 → passthrough 마스터 → 슬레이브 반전): 전진은 네 바퀴가 같은 방향, 오른쪽 조향만 주면
  왼쪽 +400 / 오른쪽 −400. 클램프 400 · 700 · 1000, 데드밴드 0 · 200의 명령 격자 전체에서 어느 바퀴도 클램프를
  넘지 않았습니다.

실기 확인(2026-10-13, 바퀴 띄움, max 400 · 데드밴드 100):

- 메인보드 4장과 ESP32를 올렸습니다. 마스터 2장은 passthrough, 슬레이브 2장도 같은 소스입니다.
- `s 150`에서 출력 212(데드밴드 적용), 마스터 바퀴 2.94 km/h. 양수가 전진입니다.
- 마스터는 오른쪽 바퀴였습니다. `i 1` 뒤 네 바퀴 모두 전진 · 제자리 회전(왼쪽 전진, 오른쪽 후진)이 맞았습니다.

## 영향

- 메인보드 펌웨어는 GPL-3.0 업스트림을 고친 것이라 소스 · bin · 빌드 기록을 이 저장소 밖(로컬)에서 관리합니다.
  메인보드는 나중에 다른 모터 드라이버로 바뀔 수 있고, 그때도 "바퀴별 값을 그대로 받는다"는 이 결정의 인터페이스를 지키면
  ESP32 쪽은 그대로 쓸 수 있습니다.
- ESP32의 보드 모드 · 탱크 모드와 `v` 명령을 없앴습니다. `i`는 "좌우 바꿈"이 되었습니다.
- **버전 순서**: 2026-10-13 이전 ESP32 + passthrough 마스터는 위험합니다. 옛 보드 모드가 조향을 ±1000으로 보내서
  슬레이브 바퀴가 100 % 듀티가 됩니다. 반대 조합(새 ESP32 + 옛 마스터)은 움직임이 틀려도 클램프 안입니다.
  그래서 ESP32를 먼저 올립니다.
- 마스터가 오른쪽 바퀴라서 ESP32에 `i 1`이 저장돼 있습니다. ESP32 플래시를 전부 지우면 다시 설정해야 합니다.
- 다시 볼 조건: 같은 듀티에서 네 바퀴가 서로 끄는 문제가
  보이면(pwm 모드의 Kv 편차) `DRIVING_MODE 1`(속도 제어)를 검토합니다.
- 지상 시험 뒤 D-03에 믹싱 위치가 바뀐 것을 반영합니다.
