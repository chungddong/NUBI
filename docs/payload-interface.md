# 페이로드 인터페이스 규격 v1

스키드 스티어 모빌리티 베이스(`models/swerve_base.py`) 위에 올리는 모듈이 지켜야 할 규격.
이걸 지키면 **볼트 3개만 풀고 밀어서 1분 안에 교체**된다.

좌표계: 지면 z=0, 전방 +X, 좌 +Y, 상 +Z. 단위 mm.

![기본 베이스](images/41_skid_drawing_sheet.png)

*페이로드를 뺀 기본 베이스. 데크 위 레일 3본이 모듈이 물리는 곳이다.*

---

## 1. 기구 — 슬라이드 인터페이스

### 1.1 데크 레일

베이스가 제공하는 것. 모듈은 여기에 물린다.

```
2020 T슬롯 3본,  y = -200 / 0 / +200
x = -405 ~ +380   (뒤끝은 셸 뒷면까지, 앞끝은 380 에서 끝난다)
윗면 z = 480,  측면 슬롯 중심 z = 470
```

**레일 앞끝이 380 에서 끝나는 이유**: 모듈을 앞에서 뒤로 밀어 넣으므로, 모듈 앞벽이
레일을 가로지르면 안 된다. 뒤끝이 셸 뒷면(-405)까지 나가는 이유는 모듈 뒷면 노치를
레일 끝면이 채워야 하기 때문이다.

### 1.2 모듈이 만들어야 할 것

| 요소 | 규격 |
|---|---|
| **슬라이드 채널** | 3개, 레일당 1개. 안폭 22, 벽 5 |
| **물림 턱** | 채널 양 벽 안쪽, 깊이 2.5 × 두께 4, z=470 (레일 측면 슬롯에 들어간다) |
| **채널 스토퍼** | 채널 뒤끝 벽. 앞면이 레일 뒤끝(x=-380)에 닿아 **뒤로 밀리는 걸** 막는다 |
| **뒷면 노치** | 3개, 22 × 20, x=-405 면. 레일이 여기로 들어온다 |
| **리테이너** | 3개, 노치를 덮으며 레일 끝 중앙 보어(Ø4.2 → M5)에 손잡이 볼트. **앞으로 빠지는 걸** 막는다 |
| **스커트** | z=461~480 을 사방으로 덮는다. 데크와 모듈 사이 빈 공간을 가린다 |

### 1.3 장착 순서

```
1. 리테이너 3개를 뗀다
2. 모듈을 뒤에서 정렬해 앞으로 민다 (채널이 레일을 타고 들어간다)
3. 채널 스토퍼가 레일 뒤끝에 닿으면 정위치
4. 리테이너 3개를 M5 손잡이 볼트로 조인다
```

### 1.4 외형 규칙

```
평면 윤곽   810 × 610, 코너 R60   (본체 셸 단면을 그대로 이어 올린다)
스커트      z=461 부터. 데크 윗면(460)과 1mm 그림자선만 남긴다
개구        레일 노치 3개만. 앞·옆에서는 안 보인다
```

이 규칙을 지키면 모듈이 바뀌어도 실루엣이 하나로 이어진다.

## 3. 하중 한계

베이스 실측 기준 **공차 약 89 kg, 무게중심 z = 357**.

| 한계 | 값 | 근거 |
|---|---|---|
| 구동 모터 | 100 kg 이상 | 호버보드 허브모터 4개, 원설계가 2인승급 |
| **서스펜션** | **약 60 kg** ← 병목 | 쇼크 13 N/mm × 트래블 25 × 4 = 132kg, 이미 스프렁 약 70kg |
| 전복 (25° 유지) | CG 높이 700mm 에서 50kg / 1200mm 에서 25kg | `CG = (89×357 + m·h)/(89+m) ≤ 558` |

60kg 을 넘기려면 쇼크를 20 N/mm 급으로 바꿔야 한다.

**높이보다 무게가 먼저 걸린다.** 베이스가 무겁고 낮아서(CG 357) 전복 여유는 넉넉하다.

### 3.1 아웃리거 — 서스펜션 우회

`OUTRIGGER = True` (베이스 옵션). 팔 작업·계측처럼 **차체가 흔들리면 안 되는** 상황에서
편다.

```
피벗    상부 사이드 레일 바깥 슬롯 @ x=±360, y=±320, z=436  (셸 관통 브라켓)
암      240 × 26×22, 전개각 45°
잭      Ø34 튜브 + M18 스크류 + 발판 Ø80   ← **수직**
```

| | 접힘 | 전개 |
|---|---|---|
| 전폭 | 720 (핸들 712 대비 +8) | 1059 |
| 지지 베이스 | — | **720 × 979** (바퀴 520 × 520) |
| 전복각 | 36° | **좌우 54° / 앞뒤 45°** |

**왜 모듈이 아니라 베이스인가**: 모듈에 달면 로봇 전체 무게가 슬라이드
인터페이스(레일 슬롯에 2.5mm 물린 턱)를 통과한다. 그건 모듈을 붙잡아두는
용도지 로봇을 들어올리는 용도가 아니다.

**왜 위에서 내려오나**: `z < 248` 에서는 90° 조향 스윕이 x 151~369 를 통째로 쓴다.
남는 건 바퀴 사이(|x|<151, 앞뒤로 너무 짧다)와 11mm 짜리 틈뿐이다.
상부 사이드 레일(z=436)은 스윕 위라 x 제약이 없어 ±360 까지 벌릴 수 있다.

**잭은 수직이어야 한다.** 암과 같이 45° 로 기울이면 발판이 지면에 안 닿고
옆으로만 벌어진다 (전폭 1432, 발이 z=64 에서 멈춤). 실제 아웃리거는 암이 벌어진 뒤
수직 스크류가 내려간다.

## 4. 지금 있는 모듈

`PAYLOAD` 파라미터 한 줄로 갈아끼운다.

### `PAYLOAD = "cargo"` — 적재함

```
810 × 610 × 360, 어깨 R55 라운드, 내부 약 170 L
격벽 x=230 → 화물칸 630 + 장비베이 170
뚜껑     위로 열림, 어깨 포함(열면 800×600 전면 개방)
         내부 힌지 2(격벽 위) + 솔레노이드 잠금 + 가스 스트럿 2
         뒷면 손잡이 홈 240×55×28
화물칸   라이너 트레이 (코너 R25, 탈착 세척) + 벽면 타이다운 4
장비베이 격벽 앞면 M4 50격자 마운트판 + 바닥판, 위는 고정 지붕
전고     840        무게 약 17 kg
```

### `PAYLOAD = "flat"` — 평판

```
810 × 610, 상판 4mm, 가장자리 립 20
M6 100격자 (7 × 5 = 35점) + 타이다운 D링 6
전고 504 — 가장 낮고 가볍다 (안테나 595 보다도 낮은 유일한 구성)
```

인터페이스 검증용이자, 부피 큰 실험 장비를 그냥 묶어 싣는 용도.

### `PAYLOAD = "sensor"` — 센서 타워

```
마스트   2020 기둥 2본 (y=±100) + 가로타이 2 (z=640/810) + 대각 브레이스 4
헤드판   240 × 240 × 6 @ z=940, 코너 R20
센서     3D 라이다 Ø65 (스캔면 z=1008, 라이저 30 으로 띄움)
         팬틸트 카메라 70×90×62 @ z=745 (마스트 브라켓)
         GNSS Ø60 @ 헤드판 위 x=-90 (라이다 스캔면보다 낮다)
         IMU 36×26×12 @ 베이스판 위 x=-200 (진동 적고 회전중심 근처)
베이스   4mm 판 + M6 100격자 — 센서 추가 배치용
전고     1041
무게     약 5 kg → 무게중심 357 → 372, 전복각 36° → 35°
```

**왜 기둥 2본에 브레이스인가**: 외팔 마스트에 라이다를 얹으면 주행 진동으로
포인트클라우드가 흐려진다. 기둥 2본을 200mm 띄워 Y축 굽힘을, 전후 대각
브레이스로 X축 굽힘을 잡는다. 가로타이가 비틀림을 막는다.

**시야**: 라이다가 평면 중앙이라 360° 중 마스트 기둥 2본이 만드는 좁은 두 섹터만
가린다. 스캔면(1008)이 헤드판(946)·GNSS(961)보다 위라 자기 몸을 안 본다.

### `PAYLOAD = "arm"` — 로봇 팔 마운트

팔 자체는 구매품이다. 설계 대상은 **하중을 레일로 분산하는 마운트**다.

```
베이스판   10mm (3mm 로는 팔 모멘트에 휘어 툴 위치가 흐트러진다)
취부 보스  Ø150 × 14, M6 × 4 @ PCD 100  [가정 — 데이터시트로 확인]
분산 리브  3본, 레일 y=-200/0/+200 선상. 보스 하중을 레일로 직결
케이블     보스 중앙 Ø44 관통 → 베이스판 → 데크 그로밋
컨트롤러   200×160×90 @ x=+250 (전방). 베이 안은 이미 꽉 찼다
팔 위치    x=0 — 축간 중심. 어느 방향으로 뻗어도 전복 여유가 같다
팔 [가정]  도달 700 / 자중 12kg / 가반 3kg  (xArm6 급)
전고       938 (접힌 자세)
```

### 검토 결과

```
전복      복원 258 N·m  vs  최대도달 전도 13 N·m  →  여유 19.9배
서스펜션  코너당 4.9mm 처짐 → 기울기 1.07° → 툴 이동 약 19mm
```

**전복은 문제가 아니다. 서스펜션이 문제다.**

팔이 뻗으면 모멘트가 앞뒤 서스펜션에 힘 짝으로 전달되어 로봇이 1.07° 기울고,
그만큼 툴이 **19mm 움직인다.** 픽앤플레이스라면 비주얼 서보잉으로 덮을 수 있지만
정밀 작업은 불가능하다.

대책: **아웃리거**(아래 3.1)로 서스펜션을 우회한다. 서스펜션 락아웃은 부품이 늘고
타이어가 여전히 눌리며, IMU 역보상은 정적 처짐만 잡는다.

### `PAYLOAD = "inst"` — 계측 모듈

이 프로젝트의 숫자는 **전부 계산값**이다. 공차 89kg, 무게중심 357, 스프링 13 N/mm,
툴 처짐 19mm — 하나도 실측이 아니다. 이 모듈이 그걸 바꾼다.

```
베이스판    6mm + M6 100격자
로드셀      버튼형 Ø40 × 4 @ (x=50±210, y=±190)
시험 플랫폼  600 × 500 × 8, M6 격자 — 여기에 밸러스트를 올린다
DAQ 박스    150 × 200 × 80 + 스트로크 센서 커넥터 4채널 + 디스플레이
IMU         베이스판 위 x=250
견인 훅     후단, 인라인 로드셀 자리 + 아이볼트
전고        628
```

**시험 플랫폼은 로드셀 4개에만 닿는다.** 다른 데 닿으면 하중이 새서 못 잰다.
그래서 DAQ 박스는 플랫폼 밖(뒤쪽 베이스판)에 따로 앉혔다.

### 잴 수 있는 것 / 못 잴 것

| | 방법 |
|---|---|
| 페이로드 질량 | 로드셀 4개 합 |
| 페이로드 평면 무게중심 | 로드셀 4점 하중 배분에서 역산 |
| **서스펜션 스프링 상수** | 스트로크 센서 4채널 + 알려진 밸러스트 → 13 N/mm 가정 검증 |
| 코너 하중 | 스트로크 × 실측 스프링 상수 |
| 기울기 / 전복 한계 | IMU + 경사로에서 밸러스트 높이를 올려가며 |
| 견인력 · 등판 저항 | 후단 인라인 로드셀 |
| **바퀴별 하중** | ✗ **못 잰다** |

**왜 바퀴 하중을 못 재나**: 모듈과 데크 사이 로드셀은 그 위의 페이로드만 본다.
바퀴 하중을 직접 재려면 **외부 저울 패드 4개**(로봇을 올려놓는다) 또는
**서스펜션 계장**(쇼크 마운트에 로드셀)이 필요하다. 후자는 모듈이 아니라
베이스 개조다. 스트로크 센서로 역산하는 게 현실적인 타협이다.

### 실험 순서 제안

```
1. 빈 상태에서 스트로크 4채널 영점 → 공차 코너 하중 분포
2. 알려진 밸러스트를 플랫폼 중앙에 단계별로 올림 → 스프링 상수 실측
3. 밸러스트를 격자 위에서 옮김 → 무게중심 이동 vs 스트로크 응답
4. 밸러스트를 높이 쌓고 경사로 → 전복각 실측 (계산 33~36° 검증)
5. 견인 훅에 로드셀 → 등판·견인 저항 실측 (구동토크 1.24 N·m 가정 검증)
```

## 6. 설계하면서 알게 된 제약

기록해 둘 가치가 있는 것들. 다음 모듈을 만들 때 같은 데서 막히지 말라고.

### 라운드 스커트는 데크까지 내리면 슬라이드가 불가능하다

스커트를 데크(602 폭)까지 내리면, 라운드 코너 때문에 앞으로 갈수록 안쪽 폭이 좁아진다.
계산하면 **45mm 밖에 못 들어간다**. 그래서 스커트는 레일 구간(20mm)만 덮는다.
레일은 폭 ±210 이라 코너가 좁아져도 여유가 남는다.

### 닫힌 앞벽은 레일을 가로지른다

앞벽이 막혀 있으면 밀어 넣는 동안 반드시 레일과 부딪힌다. 레일을 중간에서 끊어도
마찬가지다(앞벽이 그 지점을 지나간다). 답은 **앞이 아니라 뒤에 노치**를 내고
**앞에서 뒤로** 미는 것이다. 노치가 레일을 타고 들어온다.

### 3mm 벽에는 걸침턱을 팔 수 없다

뚜껑을 안쪽으로 앉히는 리베이트를 10mm 파려 했는데 벽이 3mm 라 자리가 없었다.
뚜껑은 **위에 얹고 안쪽 립으로 위치를 잡는** 방식이 맞다.

### `Compound(children=...)` 는 자식을 재부모화한다

두 개를 미리 만들어 두면 나중 것이 앞 것의 자식을 빼앗아 **앞 것이 텅 빈다.**
이것 때문에 HLR 투영이 1500선 → 22선으로 죽었고, 렌더 장면이 두 번 비었다.
세 번 걸렸다. 뷰마다 그때그때 새로 묶어야 한다.
