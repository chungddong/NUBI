## 2026-11-05 (목) · 저장소: 공학 페스티벌 전시 덱 초안 — 팀 PDF 디자인에 누비 기록 채우기

## 2026-11-16 (월) · 상위 제어: 라즈베리파이로 게임패드 조종 옮기기 — 네 바퀴, 부팅 자동 실행

> 시간: 17:20 ~ 18:50 · 장소: PC · Pi "chungpi" (Raspberry Pi 4, Debian 13, `chungpi@10.78.208.2`) · 시제품 (바퀴 띄움) · 날짜 근거: 세션

Jetson에서 하던 게임패드 조종(`pad.py drive`)을 라즈베리파이로 옮겼다. 네 바퀴가 패드로 돌고, Pi를 켜면 패드 운전이
스스로 떠서 START만 누르면 된다.

### 한 일

> 우리 기존에 젯슨에서 하던거를 여기에 일부 옮겨서 작업해야겠어 우선 컨트롤러 연결해서 차량 조작 하는 것부터 해볼까?

- Pi 둘러보기: 패드 수신기(DragonRise `0079:181c`)가 꽂혀 있었다. USB의 Espressif 장치(`303a:4000`)는 바퀴 제어기가 아니라
  PC와 잇는 네트워크 장치(`usb0`, 10.78.208.2)다 — 빼지 않는다. 사용자가 `input` · `dialout` 그룹에 이미 있어 sudo 없이 패드 ·
  시리얼을 연다.
- `to_jetson.sh chungpi@10.78.208.2`로 같은 자리(`~/NUBI/experiments/…`)에 복사, 그 폴더에 `.venv`(`--system-site-packages`,
  pyserial 3.5 · numpy). `pad.py drive --fake`로 패드가 잡히는 것 확인.
- 패드 입력 기록(`pad.py show`): 버튼 · 십자 · 두 스틱이 Jetson에서 만든 `pad.json`과 그대로 맞다 (첫 60초는 패드가 꺼져 있어 입력 없음).

> esp32 랑 그 차량 모터보드랑 연결하는 그 배선도 알려줄래?

- 배선은 바퀴 제어기 README의 Wiring 표를 안내. 사용자가 한 축을 먼저 연결했다.
- 첫 연결에서 `rx`가 0. 펌웨어 `d` 진단: `frames on GPIO16 (our RX): 0 · GPIO17 (our TX): 14 <== WIRES SWAPPED` → 두 선을
  바꿔 꽂으니 초당 약 10프레임, 39.5 V. 다른 축을 GPIO26/27에 연결했을 때도 똑같이 바뀌어 있었고 바꿔 꽂아 해결.

> 지금 방향과 바퀴 움직이는 걸 보면 이걸 지금 앞쪽 휠이라고 저장해둬야겠다 지금 연결된 핀들을 앞쪽 방향으로 설정해두자

- 처음 연결한 짝(사용자가 처음에 '뒤쪽'이라 한 것)을 바퀴 방향을 보고 앞축으로 쓰기로 했다. 펌웨어는 원래 링크 A(GPIO16/17)
  = 앞축이므로 선을 그대로 두면 되고, 코드는 바꾸지 않았다. 남은 짝이 뒤축(GPIO26/27).
- 단계 100으로 두 바퀴, 이어 네 바퀴 패드 운전 — 사용자가 '잘 된다'.

> 이제 파이가 켜지면 이 start 눌러서 컨트롤러 잡고 하는게 알아서 잘 되도록 해두자

- `pad_ctl.sh`: 폴더에 `.venv`가 있으면 그 파이썬을 쓰고, 프로세스 패턴을 venv 파이썬까지 잡게(`python[0-9.]* -u pad[.]py drive`),
  `install` 뒤 옵션을 부팅 실행에 넘기게 고쳤다. Pi에서 `bash pad_ctl.sh install --level 100` → 사용자 crontab `@reboot`.
- 기록은 `~/NUBI/data/logs/pad/pad.log` (재부팅해도 남음). 처음 두 바퀴 운전 기록은 `/tmp`에 두어 재부팅으로 잃었다.

### 확인한 것

| 항목 | 값 |
| --- | --- |
| 앞축 (GPIO16/17) | `rx` 초당 약 10, 39.6 V |
| 뒤축 (GPIO26/27) | `rx2` 초당 약 10, 39.5 V |
| 맞는 방향 | 보드 헤더 4번(TX) → ESP32 16 / 26, 5번(RX) → 17 / 27 |
| 부팅 자동 실행 | 18:48:52 부팅 → 18:49:01 고리 시작 → 18:49:05 패드 잡음, 놓은 상태로 대기 |

### 발견한 문제

- Pi가 18:02쯤과 18:29(패드로 바퀴를 돌리던 중) 두 번 저절로 다시 켜졌다. 전원은 보조배터리. 그 바람에 venv의 pyserial ·
  numpy 파일이 깨져 있었고 다시 깔았다. 다시 켜진 뒤 `vcgencmd get_throttled`는 0x0이고 시스템 기록이 재부팅에 남지 않아
  원인은 확정하지 못했다 — 저전압이 가장 의심스럽다.
