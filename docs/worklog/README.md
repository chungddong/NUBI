## 양식

### 월별 파일

한 달에 파일 하나(`YYYY-MM.md`)입니다. 맨 위에 그 달의 목차 표가 있고, 그 아래로 오래된 항목부터 차례로 씁니다.
항목 하나는 한 세션(또는 하루)입니다. 항목 사이는 `---`로 나눕니다.

```markdown
## 2026-10-20 (화) · 바퀴 제어: 콘솔 입력 강건화

> 시간: 14:00 ~ 17:30 · 장소: PC · 날짜 근거: 세션 · 커밋: `abc1234` · 관련 이슈: N1

무엇을 하려 했고 어떻게 끝났는지 한두 문장.

### 한 일

#### 14:00 — 잡음 바이트 재현

...

### 확인한 것

### 남은 일
```

**제목**은 `날짜 (요일) · 영역: 제목`입니다. 날짜를 모르면 `YYYY-MM-DD 이전 (날짜 미상)`으로 씁니다.

**인용 줄**에는 있는 것만 ` · `로 이어 씁니다.

| 칸 | 무엇 |
| --- | --- |
| 시간 | `HH:MM ~ HH:MM`. 날을 넘기면 `HH:MM ~ MM-DD (요일) HH:MM` |
| 장소 | PC, Jetson "dongki", RDK "sunrise", 시제품 등. 작업 폴더가 중요하면 경로까지 |
| 날짜 근거 | 세션 기록 / 커밋 / 파일 시각 / 타 머신 — 나중에 쓴 기록이면 무엇으로 날짜를 정했는지 |
| 커밋 | 그날 커밋 해시 |
| 관련 이슈 | `firmware/wheel-controller/ISSUES.md` 번호 등 |
| 원본 | 다른 곳에서 옮겨 온 항목이면 원래 위치 |

**영역**은 아래 중 하나입니다. 새 갈래가 생기면(예: 자율주행 소프트웨어) 여기에 더합니다.

| 영역 | 무엇 |
| --- | --- |
| 차체 | `hardware/vehicle/` — 차체 설계, 부품 선정, 구조해석, 웹 시뮬레이터 |
| 바퀴 제어 | `firmware/` — ESP32 바퀴 제어기, 호버보드 메인보드 |
| 상위 제어 | Jetson · RDK에서 돈 것 — 장애물 가드, 초파리 뇌 주행, 나중에 ROS 2 |
| 저장소 | 저장소 구조, 문서, 도구 |

**본문 칸**은 이 순서로 쓰고, 해당 없는 칸은 뺍니다. 칸 안의 세부 갈래는 `####`로 나눕니다(시각이 있으면 `#### HH:MM — 제목`).

| 칸 | 무엇 |
| --- | --- |
| (요약) | 제목 없이 첫 단락. 무엇을 하려 했고 어떻게 끝났는지 |
| 배경 | 시작할 때의 상태 |
| 한 일 | 한 것. 사용자 질문은 `>` 인용으로 그대로 남기면 나중에 맥락이 보입니다 |
| 결정 | 무엇을 왜 골랐는지. 오래 남을 결정은 DECISIONS.md(D-NN)나 `docs/decisions/`에 쓰고 링크 |
| 확인한 것 | 수치와 측정 조건 |
| 발견한 문제 | 새로 드러난 문제. 이슈 번호를 붙였으면 번호로 |
| 남은 일 | 다음에 할 것 |
| 교훈 | 다음에 같은 실수를 안 하려고 남기는 것 |
| 이후 달라진 것 | 나중에 다시 읽으며 달라진 점을 덧붙일 때 (차체 일지는 2026-09-15 기준) |
| 참고 | 기록 공백, 확실하지 않은 것 등 |

### 주제별 기록 (topics/)

여러 날에 걸친 한 주제를 정리한 기록입니다. 파일 이름은 `<영역>-<주제>.md`(소문자 kebab-case), 맨 위에 제목과
인용 줄(영역 · 기간 · 원본)을 둡니다. 긴 디버깅 과정도 여기에 쓰고 일지에서는 링크만 겁니다.
