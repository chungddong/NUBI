# 시스템 개요

누비의 계층 구성과 계층 사이의 인터페이스를 정리한 문서입니다. 2026-10-13 기준이며, 바퀴 제어기
쪽 내용은 [lolind32-wheel](https://github.com/chungddong/lolind32-wheel)의 README와 WORKLOG에서
옮겨 왔습니다. 그 저장소가 `firmware/wheel-controller/`로 들어오면 링크를 바꿉니다.

## 계층

```
상위 컴퓨터   Jetson Orin Nano / RDK 보드
   │  USB 시리얼 115200, 텍스트 명령
   ▼
바퀴 제어기   LOLIN D32 (ESP32)
   │  UART 19200 8N1, 바이너리 프레임
   ▼
모터 보드     호버보드 GD32 메인보드 ×4 (마스터 + 슬레이브 2쌍)
   │  3상 + 홀센서
   ▼
구동         6.5" BLDC 허브모터 ×4
```

| 계층 | 하는 일 | 하지 않는 일 |
| --- | --- | --- |
| 상위 컴퓨터 | 센서 처리, 장애물 판단, 주행 명령 생성 | 바퀴 하나하나의 듀티 계산 |
| 바퀴 제어기 | 명령 클램프 · 램프 · 데드맨 · 호스트 워치독, 탱크 모드 좌우 믹싱, 폰 조종 페이지 | 인식, 경로 계획 |
| 모터 보드 | BLDC 정류, 보드 모드에서 속도 · 조향 믹싱, 텔레메트리 송신 | 상위 명령 해석 |

## 인터페이스 1 — 상위 컴퓨터 ↔ 바퀴 제어기

USB 시리얼(CH340), 115200, 줄 단위 텍스트 명령입니다.

| 명령 | 동작 |
| --- | --- |
| `s <n>` | 목표 속도 |
| `t <n>` | 목표 조향 |
| `x` 또는 빈 줄 | 정지 |
| `m <n>` | 클램프 상한, 0..1000 |
| `w <0\|1>` | 호스트 워치독 켜기/끄기 |
| `h` | 하트비트 (워치독만 갱신) |
| `v <0\|1>` | 구동 모드: `0` 보드 모드, `1` 탱크 모드 (플래시에 저장) |
| `i <0\|1>` | 탱크 모드에서 링크 B 반전 (저장) |
| `b <n>` | 데드밴드 듀티, `0`이면 끔 (저장) |
| `l <n>` | LED/상태 비트 |
| `?` | 도움말과 현재 설정 |

상위 컴퓨터 쪽 래퍼는 두 가지가 만들어져 있습니다.

- RDK `autocar/hoverlink.py` — 포트 자동 탐색, 텔레메트리 파싱, `w 1` + 250 ms 간격 `h`
- Jetson `fly/hover_link.py` — `drive(v, ω)` (+v 전진, +ω 좌회전, ROS 규약)

ROS 2로 옮기면 이 둘을 하나의 `cmd_vel` 브리지 노드로 합치는 것이 자연스럽습니다.

## 인터페이스 2 — 바퀴 제어기 ↔ 모터 보드

UART 19200 8N1, CRC16-XMODEM(poly `0x1021`, init `0x0000`, 리틀 엔디언).
모터 보드 펌웨어는 RoboDurden Hoverboard-Firmware-Hack-Gen2.x (`2.1.8 master uart.bin`, plain UART 빌드)입니다.

| 방향 | 크기 | 시작 바이트 | 내용 |
| --- | --- | --- | --- |
| 제어기 → 보드 | 9 B | `'/'` (0x2F) | 속도 −1000..1000, 조향 −1000..1000, 마스터/슬레이브 상태 비트 |
| 보드 → 제어기 | 22 B | `0xABCD` | 좌우 속도(100× km/h), 전압(100× V), 좌우 전류(100× A), 좌우 오도메트리(홀 스텝) |

보드는 약 10 Hz로 먼저 텔레메트리를 보내고, 제어기도 10 Hz로 명령합니다. 링크 A는
GPIO16/17, 링크 B는 GPIO26/27입니다.

## 구동 모드

| | 보드 모드 (`v 0`, 현재 기본) | 탱크 모드 (`v 1`) |
| --- | --- | --- |
| 링크 구성 | 링크마다 마스터 + 슬레이브 한 쌍 | 링크 A = 왼쪽, 링크 B = 오른쪽 마스터 |
| 믹싱 | 모터 보드가 함 | ESP32가 함: `left = speed + turn`, `right = speed − turn` |
| 제자리 회전 | 안 됨 | 됨 |
| 상태 | 4륜 회전 확인 (바퀴 띄움) | 구현만 함, 지상 주행 전 |

보드 모드에서는 풀 조향 시 안쪽 바퀴가 최대 약 12 % 역방향 듀티만 받는데, 이 모터는 약 20 %는
있어야 움직이므로 회전이 약합니다. 탱크 모드와 메인보드 커스텀 펌웨어(`SLAVE_SAME_SIDE`)가 그
대안입니다.

## 안전장치 (바퀴 제어기)

- **클램프** — 부팅 시 상한 400/1000. 데드밴드 재매핑까지 포함해 와이어로 나가는 값을 제한
- **램프** — 속도 변화 100 ms당 20, 조향 100 ms당 100. 정지는 램프 없이 즉시
- **데드맨** — 텔레메트리가 끊기면 명령을 0으로
- **호스트 워치독** — `w 1`로 켜면 하트비트가 끊길 때 정지

## 상위 컴퓨터 현황

| 보드 | 환경 | 한 것 |
| --- | --- | --- |
| RDK "sunrise" | aarch64 Ubuntu 22.04, ROS 2 Humble | Xtion 깊이 카메라 전방 장애물 가드 → ESP32 시리얼 인터록 (2026-09-17) |
| Jetson Orin Nano 8 GB "dongki" | JetPack 6.2, CUDA 12.6 | 초파리 전뇌 시뮬레이션 폐루프 주행, 바퀴 띄움 (2026-09-18) |

센서는 지금까지 ASUS Xtion 깊이 카메라만 썼습니다. 약 50 cm 안쪽은 깊이가 0으로 나오므로
가드에서는 유효 픽셀이 10 % 미만이면 BLIND로 보고 정지 처리했습니다.

## 알려진 문제

- CH340이 포트를 열 때 흘리는 잡음 바이트가 `speed 1`로 해석되고, 데드밴드 때문에 실제 20 %
  듀티로 움직입니다. 콘솔 입력 강건화가 먼저입니다.
- 상위 프로세스가 강제 종료되면 호스트 워치독이 켜진 채 남아 폰 조작이 막힙니다.
- 조향 응답이 약 0.5 s 늦습니다 (조향 램프 + 상위 루프 5 Hz).
- 텔레메트리 L/R과 실제 왼쪽/오른쪽 바퀴의 대응이 문서마다 다르게 적혀 있어 실측으로 확정해야
  합니다.
- 메인보드가 몇 분 유휴 상태면 스스로 꺼집니다.

## 정해야 할 것

결정이 나면 [decisions/](../decisions/)에 기록합니다.

- 구동 구성: 보드 모드 4륜 유지 / 탱크 모드 / UARTBUS로 4장 독립 제어
- 주 컴퓨터: Jetson Orin Nano와 RDK 중 무엇을 주력으로 쓸지, 혹은 역할을 나눌지
- 센서 구성: 깊이 카메라 외에 라이다를 둘지
- 전원과 안전 계통: 배터리, 비상정지, 범퍼
