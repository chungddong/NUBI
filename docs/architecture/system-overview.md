## 계층

```
상위 컴퓨터   Jetson Orin Nano
   │  USB 시리얼 115200, 텍스트 명령
   ▼
바퀴 제어기   LOLIN D32 (ESP32)
   │  UART 19200 8N1 ×2 (링크 A · B), 바이너리 프레임
   ▼
모터 보드     호버보드 2세대 분리형 보드 ×4 (마스터 + 슬레이브 2쌍)
   │  3상 + 홀센서
   ▼
구동         6.5" BLDC 허브모터 ×4, 스키드 스티어
```

| 계층 | 하는 일 | 하지 않는 일 |
| --- | --- | --- |
| 상위 컴퓨터 | 센서 처리, 장애물 판단, 주행 명령 생성 | 바퀴 하나하나의 듀티 계산 |
| 바퀴 제어기 | 명령 클램프 · 램프 · 데드맨 · 호스트 워치독, 좌우 믹싱(바퀴별 듀티 계산), 폰 조종 페이지 | 인식, 경로 계획 |
| 모터 보드 | BLDC 정류, 받은 바퀴별 듀티를 그대로 구동(passthrough), 텔레메트리 송신 | 믹싱, 상위 명령 해석 |

## 인터페이스 1 — 상위 컴퓨터 ↔ 바퀴 제어기

USB 시리얼(CH340), 115200, 줄 단위 텍스트 명령입니다.

| 명령 | 동작 |
| --- | --- |
| `s <n>` | 목표 속도 |
| `t <n>` | 목표 조향, 클램프 기준 비율 (+ = 우회전) |
| `x` 또는 빈 줄 | 정지 |
| `m <n>` | 클램프 상한, 0..1000 |
| `w <0\|1>` | 호스트 워치독 켜기/끄기 |
| `h` | 하트비트 (워치독만 갱신) |
| `i <0\|1>` | 좌우 바꿈: `1`이면 마스터가 오른쪽 바퀴 (플래시에 저장) |
| `b <n>` | 데드밴드 듀티, `0`이면 끔 (저장) |
| `l <n>` | LED/상태 비트 |
| `?` | 도움말과 현재 설정 |

모든 명령은 글자로 시작합니다. 2026-10-13부터 숫자만 보내는 속도 단축 명령은 없앴고, `|s|` · `|t|` < 50은 0으로
처리합니다. 구동 모드 명령 `v`도 없앴습니다(아래 "구동 방식").

상위 컴퓨터 쪽 래퍼는 두 가지가 만들어져 있습니다.

- RDK `autocar/hoverlink.py` — 포트 자동 탐색, 텔레메트리 파싱, `w 1` + 250 ms 간격 `h`
- Jetson `fly/hover_link.py` — `drive(v, ω)` (+v 전진, +ω 좌회전, ROS 규약)

ROS 2로 옮기면 이 둘을 하나의 `cmd_vel` 브리지 노드로 합치는 것이 자연스럽습니다.

## 인터페이스 2 — 바퀴 제어기 ↔ 모터 보드

UART 19200 8N1, CRC16-XMODEM(poly `0x1021`, init `0x0000`, 리틀 엔디언).
모터 보드 펌웨어는 RoboDurden Hoverboard-Firmware-Hack-Gen2.x 계열의 plain UART 빌드입니다. 마스터는
믹싱을 뺀 **passthrough** 빌드, 슬레이브는 같은 소스의 빌드입니다. 메인보드 펌웨어는 GPL-3.0 업스트림을 고친 것이라
이 저장소 밖(로컬)에서 관리하고, 나중에 다른 모터 드라이버로 바뀔 수 있습니다. 바퀴 제어기는 아래 프레임 의미만 기대합니다.

| 방향 | 크기 | 시작 바이트 | 내용 |
| --- | --- | --- | --- |
| 제어기 → 보드 | 9 B | `'/'` (0x2F) | `iSpeed` = 마스터 바퀴 듀티, `iSteer` = 슬레이브 바퀴 듀티 (각 −1000..1000), 마스터/슬레이브 상태 비트 |
| 보드 → 제어기 | 22 B | `0xABCD` | 좌우 속도(100× km/h), 전압(100× V), 좌우 전류(100× A), 좌우 오도메트리(홀 스텝) |

보드는 약 10 Hz로 먼저 텔레메트리를 보내고, 제어기도 10 Hz로 명령합니다. 링크 A는
GPIO16/17, 링크 B는 GPIO26/27입니다. 마스터 ↔ 슬레이브 헤더의 + 핀은 12 ~ 15 V이므로 ESP32에
물리면 안 됩니다 (D-03).

## 구동 방식

보드 짝은 D-03 그대로 앞축 · 뒤축 단위입니다. 링크 A = 앞축 마스터 + 슬레이브, 링크 B = 뒤축이고, 두 마스터는
**오른쪽** 바퀴에 붙어 있습니다(2026-10-13 실측. ESP32에 `i 1` 저장). 믹싱은 ESP32가 하고, 두 링크에 같은 (왼쪽, 오른쪽) 값을 보냅니다.

```
turn  = steer × max / 1000
left  = clamp(speed + turn, ±max)      → 프레임 iSpeed (마스터 바퀴)
right = clamp(speed − turn, ±max)      → 프레임 iSteer (슬레이브 바퀴)
```

조향만 주면 제자리 회전하고, 어느 바퀴도 클램프를 넘지 않습니다. 마스터는 슬레이브에 부호를 뒤집어 보내고 축의
두 바퀴는 마주 보고 달려 있으므로, 같은 값이면 같은 방향으로 굴러갑니다.

2026-10-13 전에는 모터 보드가 믹싱했습니다(보드 모드). 그 믹싱은 곱셈식이라 제자리 회전이 안 되고, 풀 조향에서도
안쪽 바퀴가 역방향 듀티를 최대 약 12 %만 받았습니다. 이 모터는 약 20 %는 있어야 움직입니다. 그래서 마스터
펌웨어에서 믹싱을 뺐습니다. 같은 쪽 앞 · 뒤를 한 짝으로 묶는 탱크 4륜(`SLAVE_SAME_SIDE`) 계획은 이 방식으로
대신했습니다.

**상태**: 2026-10-13에 ESP32와 메인보드 4장(마스터 passthrough, 슬레이브도 같은 소스)을 모두 올렸고, 바퀴를 띄운
시험에서 네 바퀴의 전진 · 제자리 회전 방향이 맞았습니다. 바닥 주행은 아직입니다. 이 프레임 의미는 passthrough 마스터가
있어야 맞습니다. 2026-10-13 이전 ESP32 빌드는 조향을 ±1000으로 보내므로 passthrough 마스터와 만나면 슬레이브
바퀴가 100 % 듀티로 돕니다. ESP32를 먼저 올리고 마스터를 굽습니다.

## 안전장치 (바퀴 제어기)

- **클램프** — 부팅 시 상한 400/1000. 데드밴드 재매핑까지 포함해 와이어로 나가는 값을 제한
- **램프** — 속도 변화 100 ms당 20, 조향 100 ms당 100. 정지는 램프 없이 즉시
- **데드맨** — 텔레메트리가 끊기면 명령을 0으로
- **호스트 워치독** — `w 1`로 켜면 하트비트가 끊길 때 정지 (기본은 꺼짐)

## 차체 설계가 바퀴 제어기에 요구하는 것

차체 설계 결정에는 ESP32가 맡는 일로 적혀 있지만, 펌웨어에는 아직 없는 기능입니다.

| 요구 | 근거 | 펌웨어 |
| --- | --- | --- |
| 보드 전원 핀(`DISABLE_BUTTON`)을 GPIO로 켜고 끄기 | D-03 · D-05 | 없음 |
| 컨택터 출력 전압 감지 → 끊기면 속도 0 + 래치 | D-05 · D-20 | 없음 |
| 전조등 PWM (MOSFET 모듈) | D-11 | 없음 |
| Jetson 명령이 끊기면 정지 | D-03 | 호스트 워치독 있음. 기본이 꺼짐이라 켜는 쪽으로 바꿀지 검토 |
| 비상정지 시 "정지 유지" 먼저, 컨택터 차단은 나중 | D-19 제안 (결정 대기) | 없음 |
| 메인보드 전류 제한 `DC_CUR_LIMIT` 보드당 7 A | D-03 · D-04 | 메인보드 펌웨어 설정(저장소 밖). 지금 15 A, 바닥 주행 뒤 정함 |

## 상위 컴퓨터 실험 현황

| 보드 | 환경 | 한 것 |
| --- | --- | --- |
| RDK "sunrise" | aarch64 Ubuntu 22.04, ROS 2 Humble | Xtion 깊이 카메라 전방 장애물 가드 → ESP32 시리얼 인터록 (2026-09-17) |
| Jetson Orin Nano 8 GB "dongki" | JetPack 6.2, CUDA 12.6 | 초파리 전뇌 시뮬레이션 폐루프 주행, 바퀴 띄움 (2026-09-18) |

Xtion은 약 50 cm 안쪽 깊이가 0으로 나오므로, 가드에서는 유효 픽셀이 10 % 미만이면 BLIND로 보고
정지 처리했습니다.

차체 웹 시뮬레이터에서도 점유 격자 + A* + 순수 추종으로 자율주행을 돌려 보았습니다. 복도 27 m를
60 s에 도착했습니다 (D-19, [sim/](../../hardware/vehicle/models/vehicle/sim/README.md)).

## 알려진 문제

바퀴 제어기 전체 목록과 우선순위는 [wheel-controller ISSUES](../../firmware/wheel-controller/ISSUES.md)에 있습니다.

- CH340이 포트를 열 때 흘리는 잡음 바이트가 `speed 1`로 해석되고, 데드밴드 때문에 실제 20 %
  듀티로 움직입니다. 2026-10-13에 고쳐 ESP32에 올렸습니다(N1).
- 상위 프로세스가 강제 종료되면 호스트 워치독이 켜진 채 남아 폰 조작이 막힙니다.
- 조향 응답이 약 0.5 s 늦습니다 (조향 램프 + 상위 루프 5 Hz).
- (해결 2026-10-13) 텔레메트리 L은 마스터 바퀴이고, 마스터는 오른쪽 바퀴입니다. ESP32의 좌우 바꿈(`i 1`)으로
  명령과 표시를 맞춥니다.
- 메인보드가 몇 분 유휴 상태면 스스로 꺼집니다 (D-03도 8분 무동작 꺼짐 설정 확인을 요구).

## 정해야 할 것

- **D-03의 믹싱 부분 개정** — 차체 설계 D-03은 앞축 · 뒤축 단위로 짝을 짓고 두 짝에 같은 (속도, 조향)을
  보내 모터 보드가 믹싱하게 했습니다(= 옛 보드 모드). 짝 구성은 그대로 두고, 2026-10-13부터 믹싱만 ESP32로
  옮겼습니다("구동 방식"). 시뮬레이터의 사각지대 분석(D-19 ①)이 전제하는 제자리 회전도 이 방식으로 됩니다.
  지상 주행 시험 뒤 D-03에 반영합니다.
- **D-19 결정 대기** — 옆 낮은 장애물 센서 추가, 비상정지 방식("정지 유지 + 상선 단락").
- **12 V 변환기 용량** — 12 V 예산이 약 4.6 A로 변환기 5 A에 빠듯합니다 (D-11). 한 단계 큰 것으로 바꿀지 정합니다.
- **D-21 진행 중** — 배선을 바닥판 위 직각 경로로 (판 닿음 2, 전선끼리 겹침 69 해결 필요).
- **RDK 보드의 역할** — 차체 설계는 Jetson 한 대 기준입니다. RDK를 계속 쓸지 정합니다.

차체 설계 결정은 DECISIONS.md(D-NN)에, 여러 계층에 걸친 결정은 [decisions/](../decisions/)에 기록합니다.
