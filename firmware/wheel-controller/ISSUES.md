# 이슈 목록 (ISSUES)

아직 열려 있는 문제와 할 일을 모아 둔다. 각 문제가 언제, 어떻게 드러났는지는
[작업 일지](../../docs/worklog/README.md)의 해당 날짜 항목에 있다.

- 번호 체계: **N** = 현장에서 드러난 것, **H** = 하드웨어·빌드물, **R** = 코드 리뷰에서 확정된 것,
  **U** = 코드 리뷰에서 나왔지만 아직 검증하지 않은 것
- 고치면 상태 칸을 `수정 (YYYY-MM-DD, 커밋)`으로 바꾸고, 그날 일지에도 한 줄 남긴다.
- **마지막 점검: 2026-10-13** — 아래는 R12·U10 일부(누비 통합 때 정리), N1, H1~H3을 빼면 전부 미수정이다.
  2026-10-13에 `src/main.cpp`를 바퀴 모드로 바꾸고([ADR 0001](../../docs/decisions/0001-wheel-board-pairing.md))
  ESP32와 메인보드 4장을 모두 올렸다. 바퀴를 띄운 시험은 통과, 바닥 주행은 전이다.

## 다음에 할 일 (우선순위)

1. **바닥 주행 시험**: 전진, 제자리 회전, 데드밴드 `b` 튜닝(바닥에서 잰 값은 약 200, 지금 저장값 100). 결과로
   D-03과 ADR 0001을 갱신하고, 보드당 전류 제한(D-03은 7 A)을 정한다. 메인보드 쪽 반영은 저장소 밖(로컬)에서 한다.
2. **R5**(버튼을 떼면 램프로 감속)과 **R1**(텔레메트리만 보는 두 번째 페이지가 조종자 워치독을 살려 둠)은 바닥 주행에서
   바로 체감되므로 리뷰 수정 중 먼저 한다.
3. 리뷰 수정 순서: R1·R2·U3(웹 정지 무결성: 조종자 식별 + 시퀀스 번호 + 0도 재전송) → R5(손 떼면
   즉시 정지) → N2(워치독 해제 경로) → R6(진단 후 시각 스탬프) → R3·U1(도구 워치독·포트 열기)
   → 문서(R10·R11·R12)
4. 상위 프로젝트의 요청: **N3**(전진 전용 인터록 `o <n>`), **N4**(ESP32 믹싱의 조향 램프 재검토)
